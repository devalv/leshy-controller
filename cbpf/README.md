# cbpf/l4-filter

Программа фильтрации TCP-трафика на основе eBPF

## Назначение
Данная программа представляет собой фильтр сетевого трафика, реализованный с использованием технологии [eBPF](https://ebpf.io/) (Extended Berkeley Packet Filter) и предназначена для контроля доступа к защищаемым TCP-портам.

## Требования

* Ядро Linux с поддержкой eBPF
* Поддержка BPF Type Format (BTF)
* Возможность загрузки eBPF-программ в подсистему трафик-контроля (TC)

## Сценарии использования

* Защита Glint, RDP, VNC, SSH и других сервисов - [обобщённая схема работы](../docs/cbpf/schema.drawio)
* Реализации временного доступа по IP-адресу
* Мониторинга и контроля сетевого трафика

## Основная логика
Программа перехватывает все TCP-пакеты на указанном сетевом интерфейсе и применяет к ним следующие правила:

1. Проверка порта назначения:
    * Если порт не защищен - пакет пропускается
    * Если порт защищен - требуется дополнительная авторизация

2. Двухуровневая фильтрация для защищаемых портов:
    * Уровень 1 (Active flows): Если соединение уже установлено и активно
    * Уровень 2 (Pending sources): Если IP-адрес источника предварительно авторизован для доступа к порту

### Типы пакетов

* SYN-пакеты (начало соединения)
    1. Если IP+порт авторизованы в pending - создается активное соединение в active_flows
    2. Если не авторизованы - отправляется RST-пакет и соединение блокируется

* Пакеты установленных соединений
    1. Проверяется наличие в active_flows
    2. Если найдено - срок жизни продлевается
    3. Если не найдено, но IP+порт есть в pending - создается запись в active_flows

### Компоненты системы

1. l4_active_flows
    * Тип: LRU-хэш (автоматическое удаление старых записей)
    * Назначение: Хранение активных TCP-соединений
    * Ключ: 5-tuple (source IP, dest IP, source port, dest port, protocol)
    * Значение: Время истечения (наносекунды)
    * Лимит: 32768 записей

2. l4_pending_src
    * Тип: Хэш-таблица
    * Назначение: Авторизованные IP+порт для доступа к защищенным портам
    * Ключ: source IP (4 байта) + dest port (2 байта)
    * Значение: Время истечения авторизации
    * Лимит: 65536 записей

3. l4_guarded_port
    * Тип: Хэш-таблица
    * Назначение: Список защищенных портов
    * Ключ: Номер порта (network byte order)
    * Значение: Флаг (1 - защищен)
    * Лимит: 256 портов

4. l4_stats
    * Тип: Массив (1 элемент)
    * Назначение: Статистика работы фильтра
    * Содержит: счетчики разрешенных/заблокированных пакетов, попаданий в кэш и т.д.
5. l4_logs
    * Тип: Ring buffer
    * Назначение: Логирование событий для отладки
    * Лимит: 64 КБ

### Ключевые константы

* **ACTIVE_ALLOW_NS**: Время жизни активного соединения (300 секунд)

* Порядок байтов: все сетевые данные хранятся в network byte order (big-endian)

## Алгоритм обработки пакета

```plaintext
1. Извлечение заголовков Ethernet, IP, TCP
2. Построение 5-tuple ключа
3. Проверка, защищен ли порт назначения:
   - Нет → пропустить пакет
   - Да → продолжить проверку
4. Проверка активных соединений:
   - Найдено и не истекло → продлить срок, пропустить пакет
5. Проверка pending авторизации:
   - IP+порт авторизованы → создать active flow, пропустить пакет
   - Истекло → удалить из pending
6. Пакет не авторизован:
   - SYN → отправить RST, затем отбросить
   - Другие флаги → просто отбросить
```

## Особенности реализации

1. Автоматическая очистка
    * LRU-мапа: active_flows автоматически удаляет старые записи

    * Проверка истечения: pending_src проверяет сроки при каждом доступе

2. Ответ на SYN-пакеты

    Программа отправляет RST-пакет в ответ на заблокированные SYN-запросы, что позволяет клиентам получить уведомление о недоступности порта.

3. Порядок байтов
    Все сетевые данные (IP-адреса, порты) сохраняются и обрабатываются в network byte order для обеспечения согласованности.

4. Статистика и логирование
    * Подробная статистика по всем типам событий

    * Ring buffer для отладки в реальном времени (bpftool)

    * Атомарные операции для корректного подсчета в многопроцессорной среде

## Установка и запуск для тестирования

Тесты отсутствуют, из-за сложности тестирования связки и генерации скелетонов. Добавление тестов запланировано в следующей релизной версии программы.

### Запланированные тесты

* test_non_guarded_port - проверка пропуска пакетов на незащищенные порты
* test_guarded_port_no_auth - проверка блокировки SYN пакетов на защищенные порты без авторизации
* test_active_flow_hit - проверка пропуска трафика по активным флоу
* test_pending_promotion - проверка авторизации через pending записи и создания активных флоу
* test_expired_pending_cleanup - проверка очистки истекших pending записей
* test_rst_generation - проверка генерации RST пакетов для заблокированных SYN
